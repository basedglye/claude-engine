## 1. What is right

**`DEFAULTS.fraudRatePermille: 0 → 200`** is the ruling, implemented in one
line with a comment that names the ruling and the review finding it came from.
The shipped game now spawns fraud. Good.

**The non-vacuity pair** (`apps/hotel/scripts/test.mjs`) is exactly the right
shape and I want to call it out: it runs 200 guests at `DEFAULTS`' own rate and
asserts ≥1 planted violation, then re-runs the identical stream with the rate
forced to 0 and asserts **zero**. That second half is what makes it a real
gate — it fails loudly if the default regresses to 0 *and* if the plant path
silently stops working, which a one-sided ">0" check would not catch. It also
reads `DEFAULTS.fraudRatePermille` rather than hard-coding 200, so the test
tracks the constant instead of duplicating it.

**RESERVA `ACCEPT`/`DENY` y=440 → y=104.** I verified the non-overlap claim
by hand against `paintSpec`, in every state the screen can be in, rather than
taking the comment's word:

- *No guest presenting*: only `"No guest presenting."` at y=20. Clear.
- *Presenting.* The left document column starts at y=32 and steps `GLYPH_H=8`
  per line with a 2 px gap between doc blocks. Guest documents are exactly two
  fixed types (`game.ts:993-994`): `id` with 3 fields and `resSlip` with 2.
  Sorted, that is `[id]` header 32, fields 40/48/56, gap → 66; `[resSlip]`
  header 66, fields 74/82 → ends at 90. **Last painted pixel y=90.**
  ACCEPT/DENY occupy 104–122. Clear by 14 px.
- *One document only* (shorter block): ends earlier still. Clear.
- *After accept*: `selectedRoomEntity` resets and `data.queue` goes away →
  back to the "No guest" state. Clear.
- Right column: `RESERVATION ON FILE` at x=300 y=32ff and `PROCEDURES` from
  y=140 — different column (x≥300) from the buttons (x=8..208), so no
  collision on either axis. `VACANT ROOMS` header is at y=208, list at 220.

The comment's arithmetic is right and the reasoning ("two FIXED doc types") is
grounded in the only place documents are written. `layoutRects` and
`paintSpec` both use the same `ACCEPT_RECT`/`DENY_RECT` constants, so the hit
box moved with the paint — no chance of an invisible-but-clickable button.
