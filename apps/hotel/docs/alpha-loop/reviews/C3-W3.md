## 2. P1 — the wall-surface channel is correct

`RoomOccupancy` now carries `wallSpanBlocked`, a per-side `Uint8Array` on a
channel deliberately separate from the floor `blocked` grid, and
`placeOnWallSurface` calls `blockWallSpan` before returning. The reasoning in
the comment ("a painting above a dresser is legal, but two wall-mounted items
must never share a span") is the right model — a second floor-grid channel
would have wrongly forbidden the legal case.

I checked the indexing trap this design invites, because it is the one that
would have made the fix silently vacuous: `wallSpanIdx` divides `along` by
`GRID_M`, so if `along` were a world coordinate the indices would blow past
the array and clamp to its last slot, and one painting would block the whole
wall. It is not: `wallRuns` (`placement.ts:214-241`) generates `from`/`to` as
room-local offsets in `[0, widthM|depthM]`, and `wallPoint` adds `room.xM0`
only at the end. Array sizes are `ceil(dim/GRID_M) + 2`, which covers the
range with headroom. Correct.

`freeSubSpans` intersects the floor-level run with the wall channel using the
same merge-adjacent-free-samples shape as `wallRuns` itself, which is the
right call — one algorithm, one level up, rather than a second bespoke
scanner. The `clearanceM` parameter is well specified.

## 6. Invariants

Everything in this lane is under `apps/hotel/src/render/**` — a host root, not
a sim root — so `Math.*` and Three.js use is legal and `check-purity.mjs`'s
sim-side bans do not apply. No RNG is introduced: the wall channel is a pure
function of geometry, so placement stays deterministic without touching the
seeded streams, and no generated mesh data feeds back into sim state
(invariant 2's asset-synthesis clause). No `setComponent` path is touched
(invariant 6 not engaged). The removal of the `localStorage` perturbation
switch from `buildOccupancy` also closes the CLAUDE.md "no dev/debug commands
reachable from production builds" finding C2-W4 raised in passing.
