integer tick constants (20/40/60/80/100); no `Math.*`, no wall-clock, no
`Date.now()`. `opened` is plain state hashed with the component — replay-safe.

→ same `elapsed` → same node list).

view.tick` on every `{ kind: "open" }` input, and nothing else resets it, so
a re-open always restarts the reveal from the header — matches the brief's
"read tonight's numbers again" intent.

Star-tier line: prints the live `data.stars`, explicitly *not* a delta,
with an honest comment explaining why (no `previousStars`-style field
plumbed). This is a correct call — inventing a delta from data that doesn't

not silently dropped.

## W2 — decor.ts painting canvas

Root cause confirmed as diagnosed: canvas mesh was pinned to a fixed
`z = 0.025` while the loaded glTF frame's own front face (via
`fitToFootprint`) could land at or past that plane, occluding/z-fighting the
canvas. Fix computes the canvas z from the same `footprint.d` used for
`upgrade()`'s fitting call (`footprint.d / 2 + 0.01`), so the two numbers
can't drift apart — good defensive tie rather than two independent magic
numbers.

Verified visually: `tier2-painting-broken.png` vs `tier2-painting-fixed.png`
diff bbox at (359,15)-(516,237) — the painting region only. Cropped/zoomed
comparison shows the frame's near edges fully drawn in front of the canvas
in "fixed" vs partially hidden behind the canvas plane in "broken" — a real,
visible change, not a no-op screenshot pair.

Host-only file, no sim/purity/golden implications — matches the brief's
scope (`decor.ts` only, no RNG, no `setComponent`).
