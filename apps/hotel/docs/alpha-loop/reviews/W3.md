## Fix-list

### 1. BLOCKING — the end card fires at tier 1, not tier 2

`COMPLETING_EVENT[8]` is `"hotel.renovated"` with no check on the
payload's `to`. The alpha has **two** renovations (0→1 and 1→2). As
written, the first one — becoming a mid-tier Hotel — completes step 9,
sets `done = true`, and shows *"The Grand Foyer opens"*. The player then
gets the game's closing beat while standing in a half-renovated building,
and the walkthrough goes permanently silent for the entire second half of
the arc, which is exactly the stretch a first-time player most needs it.

The brief's step table (§4.2) says the end card comes from
`hotel.renovated` **with `to === 2`**, and the vision's loop item 7 is
"Reach tier 2: an end card". Required:

- Step 9 completes only on `hotel.renovated` where
  `payload.to === 2` (or, equivalently, on `input.hotel.tier === 2` —
  either is fine, but pick one and say which in the code comment).
- After a `hotel.renovated` with `to === 1`, the step **re-arms**: it goes
  back to not-done and its affordability gate re-evaluates against the
  *new* `renovateCostMinor` (which W1's view supplies as the cost of the
  next tier). The player is prompted a second time when they can afford
  the Grand Foyer.
- `renovatedPayload` must capture the tier-2 event, not the first one, so
  the card's `day` is the day the Grand Foyer opened.

**The checker encodes the same mistake and must be fixed with it.** Four
cases assert the wrong behaviour today —
`"endCard() appears once finished"`, `"endCard day comes from the event
payload"`, `"endCard cash comes from hotel.cash"` and
`"[ooC] renovate event completes even without the affordability frame"` —
all feed `{ from: 0, to: 1 }` and expect completion. They must feed
`to: 2` for the completion cases, and gain a new case asserting that
`to: 1` does **not** produce an end card and **does** leave a live step.
This is the reason the perturbation campaign passed while the defect was
present: a green suite that agrees with the bug is not evidence.

### 2. Non-blocking — a player who already hired a clerk is told to hire a clerk

When `pointer === STEP_RENOVATE` and the renovation is not yet
affordable, `current()` returns `STEPS[STEP_HIRE_CLERK]`, whose text is
*"Open STAFF and hire a clerk."* — but reaching that pointer requires
`stepDone[7] === true`, i.e. the clerk is already hired. The checker's own
case name says the quiet part out loud: *"already-hired clerk is not asked
for again"* — while asserting that `current()` is `hire-clerk`, the step
whose text asks for exactly that.

My brief said "show step 8's text or nothing" and that ambiguity is mine,
not the worker's. Resolving it now: **return `undefined`** (show nothing)
while the renovation is unaffordable. A silent line is correct here — the
next act genuinely is "keep running the hotel", and the game has no HUD to
say so. Rename the checker case to match what it actually asserts.

### 3. Non-blocking — the checker is unreachable from any suite and unlinted

`apps/hotel/dev/**` is in the eslint ignore set, so
`walkthrough-check.mjs` is never linted (confirmed: eslint reports
`File ignored because of a matching ignore pattern`), and it needs a
hand-rolled `tsc` invocation plus an `argv[2]` path, so it is not
reachable from `npm test` or `npm run test --workspaces`. A checker that
only runs when someone remembers the incantation will stop running.

The worker correctly flagged this as wiring it could not do. **Orchestrator
action, tracked here, not a W3 task:** add the compile-and-run step to
`apps/hotel/scripts/test.mjs` (W1's file this cycle) at integration.

Also noted and **not** held against the lane: `apps/hotel/dev/**` is
declared as W2's glob in BREAKDOWN §0, and §5 of the W3 brief named this
exact path. That contradiction is mine. There is no collision in practice
— W2 does not touch this file — and the resolution is that
`apps/hotel/dev/walkthrough-check.mjs` is reassigned to W3 retroactively.

### 4. Non-blocking — `white-space: nowrap` on the hint line

`.hud-hint` is `nowrap` at a fixed `left: 50%` with a centring transform.
The longest string, *"You can afford to renovate — open LEDGER."*, will
run off both edges of a narrow viewport rather than wrapping. Add
`max-width: min(90vw, 640px)` and drop `nowrap` (or switch to
`white-space: normal` with `text-wrap: balance`). One line of CSS.
