## Verdict

**FIX-LIST — 3 items, item 1 blocking.**

The artifact itself is genuinely good and I verified its central claim
myself: it is self-contained, it boots, the sim runs, WASD moves the
player, and the four Kenney GLBs and their textures are embedded and
byte-exact. The blocking item is not the artifact — it is `netlify.toml`,
which cannot work as written, and which is the one deliverable here that
nobody would discover was broken until a deploy failed.

## Fix-list

### 1. BLOCKING — `netlify.toml` cannot build as written

```toml
[build]
  base = "apps/hotel"
  command = "npm run build -w apps/hotel"
  publish = "apps/hotel/dist"
```

Two independent errors, both fatal:

- Netlify runs `command` **from `base`**. Inside `apps/hotel`,
  `npm run build -w apps/hotel` fails: `apps/hotel/package.json` declares
  no workspaces, so there is no `apps/hotel` workspace to select from
  there. The `-w` form only works from the repo root.
- `publish` is resolved **relative to `base`**, so this asks Netlify for
  `apps/hotel/apps/hotel/dist`, which never exists.

Either drop `base` and keep the root-relative command and publish path,
or keep `base = "apps/hotel"` and make the command `npm run build` with
`publish = "dist"` — the first is safer, because the build needs the
root `node_modules` and the workspace packages either way. Whichever you
pick, say in a comment which directory the command runs in, since that is
the fact that makes the other two lines correct or wrong.

### 2. Non-blocking — the shim falls through instead of sealing

The `fetch` shim serves embedded `/assets/**` paths from its map and
**passes everything else to the real `fetch`**. I proved this by asking
the page for `/assets/textures/lobby-floor/color.jpg`: the request left
the page and hit my server. In today's artifact nothing ever asks for
such a path (the reduced manifest omits every texture and model), so the
observed request count is genuinely zero — but "no external fetches" is
currently an arrangement rather than an invariant. One added code path,
one changed manifest, or one glTF with an unexpected relative reference
and the artifact starts phoning home with no warning.

Make the shim return a synthetic `404` for any unmatched `/assets/**`
path rather than delegating. Keep the delegation for everything outside
`/assets/`. That turns the guarantee into something the shim enforces.

### 3. Non-blocking — the freshness precondition is existence-only

The header comment is honest — it says the script requires `dist/` to be
fresh and only fails when it is *missing*. But a stale `dist/` from an
earlier session builds a stale artifact silently, and this project has
already been bitten four times by exactly that class of trap (`tsc`
incremental skipping a rebuild). Compare the newest mtime under
`apps/hotel/src/` against `dist/index.html` and refuse when `src` is
newer.

Related, and recorded rather than charged to this lane: **the artifact I
built does not contain the hover-look fallback at all.** I checked —
`pointer-fallback.ts` is not in the bundle, because `main.ts` never
imports it, because that wiring is orchestrator-only. So the lane's
"verified in isolation with `requestPointerLock` mocked to reject" is the
only evidence that exists today, and the fallback gets its real test
after integration. I read the module: canvas-scoped listeners only, no
capture-phase `document` handlers, rAF-throttled emission, an
`isLocked()` guard at the top of both handlers, and a two-frame
post-request check before entering fallback mode. It matches the contract
in the brief. It just is not in the shipped file yet.

## Also confirmed

- Determinism: the emitted HTML carries no timestamp and no random id; a
  second run against the same `dist/` produced the same size and asset
  count.
- Size assertion has real headroom: 1.69 MB against a 16 MB ceiling, and
  the payload split (0.72 MB of assets vs ~1 MB of code) is what the
  brief predicted.
- The lane's own perturbations (size limit lowered to 1 KB;
  self-containment check with one asset left unembedded) are the right
  two to have chosen. I did not re-run them and say so.
